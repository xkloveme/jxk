# AGENTS.md

## Project Overview

`jxk` is a JavaScript utility library published to npm. ESM-first (`"type": "module"`), outputs both ES and CJS bundles. Source is plain `.js` with JSDoc annotations (not TypeScript), except the playground which is Vue 3 + TypeScript.

## Commands

| Action | Command | Notes |
|---|---|---|
| Generate exports | `pnpm gen` | **Must run before build.** Auto-generates `src/index.js` and `src/libNames.js` from `src/lib/` |
| Build library | `pnpm build` | Runs `gen` then `vite build`. Outputs to `lib/` |
| Run tests | `pnpm test` | Vitest. Add filename to test a single file: `pnpm test src/lib/array/chunk.test.js` |
| Type check | `pnpm typecheck` | `tsc --noEmit`. Source is `.js` with JSDoc — type errors come from JSDoc annotations |
| Lint | `pnpm lint` | ESLint with `@antfu/eslint-config`. Prettier is **disabled** |
| Dev playground | `pnpm dev` | Runs `gen` then serves the Vue playground |
| Build docs | `pnpm build:docs` | JSDoc + playground build |

**Required order for verification**: `pnpm gen` → `pnpm lint` → `pnpm typecheck` → `pnpm test` → `pnpm build`

## Source Architecture

```
src/
  index.js          # AUTO-GENERATED by `pnpm gen` — do not edit manually
  libNames.js       # AUTO-GENERATED — list of all export names
  lib/
    {category}/
      _meta.json     # Category metadata (name, describe) for docs
      {function}.js  # One function per file, default export
      {function}.test.js  # Co-located test file (vitest)
  utils/
    common.js        # Shared helpers (getValueType, tree utils, unit conversion)
    sm2/, sm3/, sm4/ # Crypto implementations
```

Categories: `analysis`, `array`, `browser`, `file`, `is`, `mask`, `misc`, `number`, `reg`, `sm`, `string`, `time`

## Code Generation (`generate.js`)

`pnpm gen` scans `src/lib/` and generates:
- `src/index.js` — re-exports all functions as `{category}_{functionName}` (e.g., `array_chunk`, `is_array`, `time_format`)
- `src/libNames.js` — array of all export names
- `categories.json` — category metadata from `_meta.json` files

**If you add a new function file**, you must run `pnpm gen` to update exports. The build script does this automatically, but tests and type checks do not.

## Adding a New Function

1. Create `src/lib/{category}/{functionName}.js` with a **default export**
2. Add JSDoc block with required tags: `@description`, `@category`, `@alias` (`{category}_{functionName}`), `@author`, `@example`
3. Optionally create `{functionName}.test.js` alongside it (vitest, import from `./functionName.js`)
4. Run `pnpm gen` to regenerate exports
5. If adding a new category, create `_meta.json` with `{"name": "...", "describe": "..."}`

## Conventions

- **Export style**: Every function file uses `export default`. Named exports are not used in `src/lib/`.
- **No TypeScript source files**: All library code is `.js` with JSDoc types. Only `test/index.test.ts` and playground use `.ts`.
- **`lib/` is build output**: Gitignored. Do not edit files in `lib/`.
- **`src/index.js` is generated**: Do not edit manually. Always regenerated by `pnpm gen`.
- **`categories.json` is generated**: Gitignored. Created by `generate.js`.
- **Formatting**: 2-space indent, LF line endings, UTF-8. ESLint `@antfu` config enforces style. Prettier is off.
- **VS Code**: ESLint auto-fix on save is configured. Format-on-save is disabled.

## Testing

- Framework: Vitest
- Test files: co-located `{name}.test.js` in `src/lib/` subdirectories
- Root `test/index.test.ts` is a placeholder (just `expect(1).toEqual(1)`)
- Run a single test: `pnpm test src/lib/array/chunk.test.js`
- Not all functions have tests — coverage is partial

## CI/CD

- **Docs deploy** (`ci.yml`): Push to `main` → `pnpm build:docs` → deploy to `gh-pages`
- **npm publish** (`npm.yml`): Push `v*` tag → `pnpm build` → `npm publish --provenance`
- **Release** (`release.yml`): Push `v*` tag → `changelogithub` for GitHub release notes
- **Version bump**: Use `pnpm release` (runs `bumpp`) which handles tag creation

## Playground

The `playground/` directory is a pnpm workspace member containing a Vue 3 REPL component (forked from `@vue/repl`). It has its own build config, linting, and type checking. Changes to the library source do not require playground changes unless the public API surface changes.
